# 上游镜像备份

用户已接受：master 保留可信备份脚本，upstream-mirror 跟随上游，Telegram 仍是一条富消息和一个含历史的源码 ZIP。

1. 先写离线集成测试：普通更新、回退、重写及无共同祖先、默认分支更名、上游控制文件变化均能镜像；master 不变，旧对象可由 ZIP 中的 Bundle 恢复。
2. sync.py 删除合并及祖先限制，读取固定仓库身份下的默认分支。独立审查确认默认令牌不能保证推送新工作流，因此快照分支只存原始源码 ZIP 和清单，提交链保留旧快照；旧 Bundle 中的源对象恢复为本地平坦 refs/archive/OID 后再抓上游。原始上游提交不推入 GitHub，防止权限拦截和执行上游工作流。
3. 工作流只执行 master 的可信脚本，不执行上游代码；取消构建依赖。投递成功后以同步时读取的成功标记为租约更新 backup-delivered，使其指向已发送快照；用快照清单里的上游 SHA 去重，支持回退并维持失败重试。
4. Telegram 缺少或损坏版本元数据时仍发送源码，以提交短 SHA 标识；保留文件大小、仓库身份及请求参数检查。
5. 更新说明，运行 Python 回归、Node 测试及工作流结构检查；提交推送，实际验证一次投递和一次无变化运行。

边界：只保证每次实际检查时观察到的 refs；两次检查之间出现又消失的提交无法捕获。上游不可访问、服务故障与 Telegram 单文件限制仍会导致失败。
